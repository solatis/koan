koan's provider-type vocabulary (`ProviderType` and `ALL_PROVIDER_TYPES` in koan/types.py -- google/anthropic/openai/bedrock/openrouter/ollama-cloud/voyage) fans out into hand-maintained dispatch tables that must stay in sync: `_PROVIDER_PREFIX` and `_KEY_REQUIRING_PROVIDERS` (koan/agents/adapter.py), `_VALID_CONNECTION_TYPES` and `LISTING_CAPABLE` (koan/web/app.py), plus the per-provider build/listing/capability dispatch branches. A provider present in the vocabulary but missing from one table raises unknown_provider at runtime or crashes app boot, not a local test. Maintain the dynamic drift-guard test in tests/test_provider_vocabulary.py (`CHAT_PROVIDER_TYPES = set(ALL_PROVIDER_TYPES) - {"voyage"}`, voyage being embedding-only and absent from the chat build/listing tables): it asserts `_VALID_CONNECTION_TYPES == set(ALL_PROVIDER_TYPES)` and `set(_PROVIDER_PREFIX) == CHAT_PROVIDER_TYPES` (bidirectional, catching the missing-table direction), plus `_KEY_REQUIRING_PROVIDERS`/`LISTING_CAPABLE <= CHAT_PROVIDER_TYPES` and key-requiring-disjoint-from-keyless, so an add or remove needs no edit to the guard.

PROVIDER_ID_MAP (koan/agents/model_catalog.py) is NOT covered by that drift guard -- test_provider_vocabulary.py imports it only for a negative-presence check, and tests/test_model_catalog.py asserts only that PROVIDER_ID_MAP covers the providers in MODEL_CAPABILITIES. PROVIDER_ID_MAP holds PRICEABLE providers (those resolvable in the genai-prices bundled snapshot); a provider with no genai-prices pricing (e.g. ollama-cloud) is intentionally omitted from both PROVIDER_ID_MAP and MODEL_CAPABILITIES, and price_for_usage tolerates the gap via `PROVIDER_ID_MAP.get(provider)` raising ValueError, which the projection fold's try/except (price_for_usage's single caller) swallows so cost shows 0. Do not "fix" such an omission by adding a placeholder mapping.

The frontend hand-syncs provider identity across copies the same change must sweep: two `ProviderType` definitions (frontend/src/components/atoms/ProviderBadge.tsx and frontend/src/store/index.ts), bridged by a cast `c.connectionType as ProviderType` in frontend/src/components/organisms/modelConfig.ts; three `LISTING_CAPABLE` sets (`LISTING_CAPABLE_TYPES` in modelConfig.ts, plus SettingsPage.tsx and ConnectionForm.tsx); plus `PROVIDER_LABELS`, `CODES`, the badge color in ProviderBadge.css, and the ConnectionForm per-provider switch case. `tsc` enforces only the copies typed against `ProviderType` (the `Record<ProviderType, ...>` maps `CODES`/`PROVIDER_LABELS`, the `ReadonlySet<ProviderType>` sets in SettingsPage/ConnectionForm). It does NOT catch: the store `ProviderType` (bridged by the cast in modelConfig.ts), the untyped `LISTING_CAPABLE_TYPES = new Set([...])` of string literals in modelConfig.ts, or the ConnectionForm per-provider switch (it has no default and returns ReactNode, which admits undefined, so a missing case compiles clean) -- confirm those three by hand. The cast-join and the untyped set live in modelConfig.ts (extracted from App.tsx when the model-config UI moved to connected components); App.tsx itself no longer carries any provider-type copy. Violating this leaves a desynced table that crashes boot or a stale frontend copy that compiles clean.
