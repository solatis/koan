koan's in-process tool layer (`koan/tools/builtin_tools.py`) caps output from the untrusted built-in `read` / `grep` / `glob` / `bash` tools pre-emptively via a `limit` parameter (default `DEFAULT_LIMIT = 500`, model-facing on all four tools — the LLM can override). The post-hoc reject ceiling (`_enforce_output_limits`, `_MAX_TOOL_OUTPUT_LINES`, `_MAX_TOOL_OUTPUT_BYTES`) is removed entirely; the pre-emptive `limit` is the only bound. Leon chose pre-emptive generator-style limiting over the prior collect-all-then-reject approach because the concern is twofold: (1) context window protection — capped partial results cost at most `limit` lines of tokens, and (2) execution time limiting — `grep`/`glob`/`bash` stop processing as soon as `limit` records are collected, so an expensive grep over a large file set terminates early rather than scanning everything. `read` is a special case: `compute_anchors` in `koan/tools/line_anchors.py` requires the full file for `~N` collision-disambiguation ordinals, so `read` reads the whole file internally but slices output to `limit` lines via `render_anchored` — no second size check. When results are capped, a truncation note is appended indicating capping and suggesting how to narrow (e.g. "Results capped at 500 match lines — narrow the pattern or path to see more"); no total count is computed, because computing the total requires processing everything, defeating both goals. Alternatives rejected: collect-all-then-reject (the prior `_enforce_output_limits` design — wastes execution time by processing the full result set before discarding it, the user's explicit concern); collect-all-then-truncate (still processes everything, defeats the execution-time goal); keeping a byte-level cap alongside the line limit (the user said "no double limitation" — the pre-emptive `limit` is the only bound). The trusted `koan_artifact_read` bypass is expressed via `limit=None` (the model-facing wrapper defaults to `None`, not `DEFAULT_LIMIT`), preserving the full-content exemption for koan-authored artifacts. Decision surfaced when the user observed a `grep` matching an excessive number of records with no pre-emptive limiting.
