koan's frontend renders the backend's SSE projection. Before this change, `frontend/src/sse/connect.ts` applied each RFC 6902 patch with `applyPatch(storeState, patch, false, false)` (fast-json-patch, `mutate=false`, which deep-clones the whole document) then spread the result into the Zustand store, and `frontend/src/App.tsx` rendered the focused agent's `conversation.entries` with an unmemoized `renderEntry` map. Because the deep clone gave every nested object a new reference on every patch and nothing was memoized, each projection patch -- including every streamed thinking/text token -- re-ran the whole render phase and re-parsed react-markdown for every committed entry: an O(history) cost per token that grew with conversation length.

Leon directed reshaping this to a Clojure reagent/re-frame model while keeping the projection backend-authoritative. The choice: (1) apply patches with Immer `produce` wrapping `applyPatch(draft, patch, false, true)` (fast-json-patch mutates the Immer draft in place) so only the touched path gets new references -- reference identity becomes the "what changed" signal; (2) coalesce incoming patches into one Zustand commit per `requestAnimationFrame`; (3) a reselect memoized-subscription layer in `frontend/src/store/selectors.ts` as the single way views read the store; (4) a per-entry `React.memo` row boundary keyed by a server-assigned entry id, plus content-memoized `Md` and a source-cached `MermaidBlock`; (5) react-virtuoso virtualization of the conversation list (`customScrollParent` over the existing `.content-column`, `followOutput` stick-to-bottom, a stable context-threaded footer) with store-driven find and copy-transcript replacing the browser-native find/select that windowing breaks; (6) tailored streaming (pending thinking as plain pre-wrapped text, pending answer text as live markdown). One additive backend change supported it: a stable server-assigned `entry_id` on every top-level conversation entry, assigned from a per-`Conversation` monotonic counter at the single fold write-back seam `_update_agent_conversation` in `koan/projections.py`, used as the virtuoso item key.

Rationale: structural sharing plus narrow memoized subscriptions collapse the per-token committed-list cost from O(history) to O(changed); virtualization bounds DOM/scroll for long runs; the projection stays backend-authoritative (the frontend still applies server-computed patches mechanically -- Immer is only the applicator, no fold logic added). New dependencies `immer`, `reselect`, `react-virtuoso` were exact-pinned. Alternatives rejected: a hand-written copy-on-write RFC-6902 applicator (would have to implement the `move`/`copy` ops `jsonpatch.make_patch` can emit; Immer + fast-json-patch handle them and the existing catch->reconnect path self-heals); persistent-immutable-structure libraries (Immutable.js / mori) closest to ClojureScript but invasive to every consumer and clashing with the camelCase-spread-into-Zustand wire format; a surgical perf-only fix without the subscription/view formalization; and a thinking/text delta-append wire op (rejected because on localhost the full-string `replace` patch cost is noise, so no protocol change was warranted for bandwidth).
