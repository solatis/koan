koan's orchestrator and subagents receive each phase's required upstream artifacts as injected conversation messages rather than reading them on demand -- a mechanism in `koan/tools/handoff_artifacts.py` modeled on the existing context-file injector (`koan/tools/context_files.py`). Leon designed it. The rule: at phase entry the required IMMUTABLE artifacts (`brief.md`, `core-flows.md`, `tech-plan.md` -- families NOT in `LIVING_DOC_FAMILIES`) are pre-seeded into the agent's `message_history` as distinct `<handoff_artifact>` user messages, append-only so the prompt-cache prefix stays valid, deduplicated per agent via `AgentState.injected_artifacts`. Living-document families (the `plan` family and `milestones.md`) are NEVER injected -- they are listed by filename for on-demand reading via `koan_artifact_read`, so a mutable document can never go stale inside the cached prefix. The per-phase immutable set is declared in `PhaseBinding.required_artifacts`; resolution and the listing happen in `_step_phase_handshake_core`, and the pre-seed in `run_agent_loop`. The same mechanism serves the executor and reviewer subagents (the reviewer injects its CONTEXT -- brief plus the charter's upstream architecture -- but READS its target artifact under review); scouts take no artifacts and are skipped. `ArtifactInfo.produced_phase_id`, stamped server-side in the projection fold at `artifact_created`, carries the phase-to-artifact association that drives the timeline handoff badges. Rationale: between phases the only real handover is the file, and injection enforces that in code rather than via an instruction the model can ignore, while preserving prompt-cache stability. Alternatives rejected: read-self (a tool-call round-trip landing content at cache-hostile positions, and only an instruction the model may skip); injecting living documents once (the injected copy goes stale as the document mutates); re-injecting changed content (a cache miss); a second pydantic-ai `ProcessHistory` processor (injects after the step prompt and couples to the context-file path -- pre-seeding keeps handovers ahead of the prompt on a code path kept separate from user steering).
