koan's provider subsystem (koan/types.py, koan/agents/adapter.py, koan/agents/model_listing.py, koan/agents/model_catalog.py, koan/web/app.py, plus the frontend provider copies) gained the `ollama-cloud` provider type on 2026-06-27; Leon directed adding Ollama Cloud support, cloud only with no local. ollama-cloud is key-requiring (an API key in the CredentialStore) and OpenAI-protocol-compatible; build_model constructs it through pydantic-ai's `OllamaModel` + `OllamaProvider(base_url=..., api_key=...)`. Unlike OpenRouterProvider (which fixes its own endpoint internally), OllamaProvider REQUIRES an explicit base_url (it raises UserError otherwise), so koan owns a fixed `OLLAMA_CLOUD_BASE_URL = "https://ollama.com/v1"` constant in koan/agents/adapter.py, imported by model_listing.py; the connection exposes no user-configurable base_url field. Live listing reuses the shared OpenAI-compatible `/v1/models` path (`_list_openai_compatible_models`), so ollama-cloud joined the listing-capable set. Leon chose the type id `ollama-cloud` (not `ollama`) to signal cloud-only, and MINIMAL capability fidelity mirroring the openrouter provider: no branch in capability_resolver, recognition, or adapter.map_thinking, so its models degrade to conservative defaults (recognized=False, thinking_modes=[]). ollama-cloud is deliberately absent from both PROVIDER_ID_MAP and MODEL_CAPABILITIES because the genai-prices bundled snapshot carries no ollama provider -- there is no valid pricing target, so cost is unavailable and shows 0. To make that explicit rather than an incidental KeyError, price_for_usage was changed to `PROVIDER_ID_MAP.get(provider)` and raises a clear ValueError for unmapped providers, which the projection fold's existing try/except (price_for_usage's single caller) swallows, keeping cost at 0 (tests/test_usage_fold.py covers that guard). Alternatives rejected: the type id `ollama` (less explicit about cloud-only); a user-configurable base_url field (implies local/proxy support, out of scope); a placeholder PROVIDER_ID_MAP entry such as ollama-cloud->ollama (misleading -- genai-prices has no ollama, so calc_price would still fail); full capability/thinking fidelity (more per-model curation than warranted). pydantic-ai's OllamaModel auto-detects the Cloud path (base_url host ollama.com, or a model id ending in -cloud) and disables supports_json_schema_output on the resolved profile; the fixed https://ollama.com/v1 base_url triggers this, and koan relies on it without extra handling.
