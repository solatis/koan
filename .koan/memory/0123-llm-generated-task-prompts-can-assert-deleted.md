This entry records a misread caught during intake on 2026-04-29. A user-supplied task prompt (generated by Claude Desktop) asserted that 'the koan_artifact_propose tool is already orchestrator-allowed in every phase, and the frontend already renders the artifact-review surface that backs it.' Both claims were false: the koan_artifact_propose backend handler had been deleted on 2026-04-26 (along with the artifact-review frontend molecules ArtifactReviewPin, ReviewBlock, ReviewComment, ReviewCommentInput, ReviewEvent). Compounding the misread, AGENTS.md's permission table still listed koan_artifact_propose as live -- the doc had drifted from the code. Intake caught the contradiction by direct grep for 'koan_artifact_propose' against the source (zero handler matches; only deletion-context comments) before trusting the task prompt. Root cause: AGENTS.md tables are hand-maintained and lag deletions; LLM-generated task descriptions consume AGENTS.md as authoritative.

**Update (feat/epoch refactor):** the source-of-truth files named in the original have moved. The tool-permission allowlist now lives in koan/tools/tool_policy.py (ROLE_PERMISSIONS + compose_toolset), not the deleted koan/lib/permissions.py; tool handlers live in koan/tools/koan_tools.py and the projection-recognized tool set in koan/agents/events.py (KOAN_MCP_TOOLS), not the removed koan/web/mcp_endpoint.py. The lesson is unchanged: verify a task prompt's claim of tool/UI availability against these source-of-truth files and recent git history, not against AGENTS.md tables.
