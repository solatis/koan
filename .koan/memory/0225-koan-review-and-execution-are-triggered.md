---
title: koan review and execution are triggered mechanically by the artifact lifecycle,
  replacing orchestrator-driven paired review phases
type: decision
created: '2026-06-19T11:19:03Z'
modified: '2026-06-22T23:57:13Z'
---

koan's phase pipeline (koan/lib/workflows.py, koan/tools/koan_tools.py, koan/phases/) was reworked so review and execution are mechanical side effects of the artifact lifecycle rather than orchestrator-issued tool calls or paired review phases. Leon designed and approved this; it was implemented on the feat/epoch branch. Model: a write-once koan_artifact_write validates the orchestrator-chosen filename against a pure artifact registry (koan/tools/artifact_registry.py) and, when the artifact class has a reviewer, spawns a fresh-context read-only reviewer sub-agent (blocking, strong model tier, no scouts), returns its freeform findings, and persists them to a koan-created <stem>.review.md sidecar; koan_set_phase("execute", plan_file=X) validates X, emits an execute_entry freeze event, spawns the executor (blocking), returns the deviation report, and emits execute_completion -- frozen/executed/exec_outcome are event-sourced ArtifactInfo fields folded in koan/projections.py. The paired review phases were collapsed into their producers (which reconcile reviewer findings inline) and the execute phase absorbed post-execution review (inline conformance verification plus a capped one-shot remediation that writes a <plan-base>-remediation-K.md successor). The phase set narrowed to {intake, core-flows, tech-plan, milestone, plan, execute, curation, frame}. Rationale Leon gave: a fresh-context reviewer has clean-room adversarial independence the author's own context lacks; the orchestrator spends no tokens performing review; and 'koan reacts to a lifecycle condition' is a uniform organizing philosophy (writing an artifact triggers its review; naming a plan for execution triggers the executor). Alternatives rejected: orchestrator-driven review/execution with a standalone koan_request_executor tool (spends orchestrator tokens, couples the reviewer to the author's context, makes execution a manual handoff); out-of-process sub-agents for isolation (koan removed the HTTP transport -- sub-agents are in-process asyncio tasks and isolation comes from task-level exception handling); per-artifact lifecycle state in a separate file or in-memory set (duplicates or defeats the replayable event log).

**Update (living-documents change, 2026-06-22):** the EXECUTION half of this entry is reversed; only REVIEW remains mechanical. koan_set_phase is now pure routing (no plan_file, no spawn), and a new koan_request_executor(plan_file?, instructions?) tool launches the executor explicitly and repeatably -- the 'standalone koan_request_executor' alternative rejected above was adopted, with Leon stating 'I was wrong' because bundling made re-execution unrepresentable under the self-transition rule. The .review.md sidecar is gone (findings are reconciled inline in a ## Review section); the -remediation-K successor chain is gone (the same plan is re-run in place); and frozen/executed/exec_outcome were removed from ArtifactInfo (the execute_entry/execute_completion events remain but their folds are no-ops). The fresh-context mechanical reviewer on koan_artifact_write, and 'review reacts to a lifecycle condition', still hold.
