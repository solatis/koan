  (run_agent_loop ModelRequestNode) with a pure classifier and live-config bounds

koan's resilience to transient provider failures was added at the one shared provider-call boundary: the ModelRequestNode stream step inside run_agent_loop (koan/agents/loop.py). Because PydanticAIAgent.run() (koan/agents/pydantic_ai.py) delegates its entire node iteration to run_agent_loop, this single wrapper covers every role -- orchestrator, scout, executor, reviewer -- so there is no per-role or per-tool retry. A pure module koan/agents/retry.py provides classify_provider_error(err) returning 'transient' or 'unexpected' (transient: request timeouts, connection errors, and HTTP 429/500/502/503/504 plus load-shed auth; everything else is unexpected) and compute_backoff_seconds(attempt, cap) (exponential, capped). The retry wrapper reads its bounds (max_retry_attempts, max_retry_wait_seconds) LIVE from app_state.provider_config.config at retry time -- not from the per-run frozen config snapshot -- so a 'Wait longer' escalation can extend an in-flight run, while model and credential resolution stay frozen-per-run. On budget exhaustion the wrapper parks on enqueue_interaction (Abort / Wait-longer, plus Proceed-unreviewed when the failing agent is a reviewer); only classifier-'transient' exceptions are caught, and unexpected faults re-raise unchanged and emit their full traceback and exception chain to the console with no user-friendly wrapper. Leon set the policy and the defaults (about 10 attempts, about a 60-second backoff ceiling); implemented on the feat/epoch branch. This provider/network retry is a separate axis from koan's recoverable-vs-unrecoverable classification of model-driven tool-call failures (which returns a structured error to the model for self-correction rather than retrying a network call).
