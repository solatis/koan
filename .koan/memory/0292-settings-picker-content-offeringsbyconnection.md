koan's Settings model picker — the orchestrator decided that Settings picker content (`offerings_by_connection`) is computed server-side from the curated `_BASE_CATALOG` in `koan/models/capabilities.py`, rendered through each available connection's route codec, rather than fetched live from the provider. For each available connection (one with a stored credential), the catalog entries are rendered through the connection's route codec in `koan/models/codecs.py`; entries that cannot be rendered (wrong vendor for the codec) return `None` and are excluded. The resulting `wire_id` is then resolved via `resolve_offering` in `koan/models/offering.py` to apply route-aware caps (prompt_caching, native_tools, etc.). The wire shape is `dict[str, list[OfferingWire]]` with `IdentityWire` and `CapsWire` per offering. Only available connections get entries. Family groupings are embedded in the offerings' identity fields (`identity.family`, `identity.version`); the frontend derives family pins client-side from this data. `resolve_families` in `koan/agents/newest_in_family.py` is now a pure function over `_BASE_CATALOG` (no network, no listing I/O) — a utility/test surface only. The async `resolve_newest_in_family`, the POST `/api/config/models/newest` endpoint, and the eager startup model-list refresh task are all deleted. `koan/agents/model_listing.py` survives as the connection Test endpoint mechanism only (`api_config_connection_list_models`); it is no longer in the Settings path. Rationale: curated-only offerings make Settings deterministic and network-free; the codec's `render()` method acts as the vendor filter, ensuring each connection shows only models it can actually serve. Alternatives rejected: all connections including unavailable get offerings — rejected because offerings are actionable picker content; unavailable connections have no actionable models. Keeping the live-listing eager task feeding Settings — rejected because its purpose was to populate Settings with live-listed models, and with curated-only offerings there is no Settings need for live listing. Decision surfaced when planning the providers refactor; the user confirmed curated-only with the Test endpoint surviving.
